# Sunny_Boy_Logger
SB_Logger is a basic data logger for SMA SB1.5 and similar series PV inverters. It can be run as a service. It creates a new log file for each day and adds one line to the log file each minute that there is a non zero power output from the inverter. Each line is also published as a JSON message to a MQTT topic, values are published as strings. The default 502 Modbus port and the default 1883 MQTT port are used. It should work with 1.5 kW and 2.5 kW inverters, for other inverters the Modbus register that are read may need to be changed. Has been used on a RPi 2, limited testing was done for a Windows target; however this has not been tested since the code changes to allow it to operate as a linux service.

## Building
Requires GNAT with Ada 2022 support, GNATCOLL and libmosquitto-dev, plus the sibling repositories DJH and Pi_Common in the parent directory. Run `gprbuild -P sunny_boy.gpr`; the same project file builds on 32 bit and 64 bit targets. Programs are written to bin/, build on a machine of the same architecture as the target.

## Configuration
Settings are read from SB_Logger_Configuration.json in the working directory, the program will not start without this file. Run configure_sb_logger in that directory to create or edit it. Parameters are the inverter name (serial number), start delay in seconds, MQTT broker, user, password and topic. User and password may be left empty if the broker does not require them. The topic must not contain the wildcards + or #. The password is obfuscated rather than securely encrypted and is sent unencrypted to the broker, restrict access to the file accordingly.

## Reliability
Loss of communications with the inverter (including the inverter being unavailable at start up or overnight) is handled internally: Modbus connect and receive operations are time limited, TCP keep alive is used and the connection is re-established at the next logging interval. Connection failures are logged once per change of state. MQTT is independent of logging: if the broker is unavailable or publishing fails the log file is still written, one event is logged when the failure is first detected and one on recovery. If the logger task fails or stops updating its heartbeat for five minutes the program exits with a non-zero status so that systemd can restart it. An example unit file, sb_logger.service, is provided; Restart=always and StartLimitIntervalSec=0 ensure systemd keeps restarting the service. Edit the paths to suit, then copy it to /etc/systemd/system/ and run `sudo systemctl daemon-reload && sudo systemctl enable --now sb_logger`.
